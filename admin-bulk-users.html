Reset Existing Accounts Off The Old Shared Password
⚠️ Anyone created via this page before 2026-07-07 was set up with the old shared default password (RMD2026!), which was hardcoded in this page's source and sat in the public GitHub repo. This sends each listed email a standard "set your password" reset link.

Important limit: this does not remotely invalidate anyone's current password — Firebase's client API won't let a director force that from here. Someone who never opens the reset email could still sign in with the old shared password until they do. If you need a hard guarantee for a specific account, use Firebase Console → Authentication → Users → that person → "Reset password", which can disable the account until they reset.

Set Up Logins for All Active RMD Birmingham Members
⚠️ Invites everyone currently in the mou_roster collection (imported via the MOU dashboard's "Manage roster" tab) who doesn't yet have a login to set one up themselves at mou-account-setup.html — they choose their own sign-in email there, which doesn't have to match whatever address is on the roster. Built 2026-09-20 to replace the old behaviour of silently creating an account at the roster's listed email, which is what caused this year's run of duplicate-account mix-ups (same person, two different emails, two different accounts). Existing accounts are always left untouched.
Before inviting anyone, this checks names against everyone who already has real account data under a different email. Anyone who looks like a possible match is held back — with a one-click check-then-apply fix right here, using the same tool that fixed this year's mix-ups by hand. Nothing is sent twice by accident either: everyone already invited but still not set up is tracked and shown separately, so you tick who to chase rather than re-invite the whole roster each time. You choose exactly who gets an email — nothing goes out until you tick names and confirm.

Change Someone's Account Email

Changes their login email everywhere on the platform in one go — Firebase Auth, and every record that's matched to them by email (people, this year's membership roster, faculty responses, Instructor Weekend registrations, MoU submissions, faculty directory). Use this instead of creating a second account, which is what caused the Laura Ann Smith duplicate earlier this year.

Note: this frees the old address for Firebase Auth to hand out again in future — it doesn't block someone from later signing up with it under a different, unrelated account. Low risk here since accounts are only ever created by a director (never public self-signup), but worth knowing.
