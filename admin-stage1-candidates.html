Step 1 — Add candidates

Paste one candidate per line: last name, first name, email, degree, student ID, year of study — matches copying columns straight out of a spreadsheet. Last name, first name, email and degree are all expected — a row missing any of them is flagged below for you to check before importing (you can still import anyway, e.g. if an email genuinely isn't known yet). Student ID and year of study stay optional — most students won't have a student ID on file, so leave that column empty rather than holding a row back. Tab or comma separated. Room isn't collected here — it's assigned automatically alongside the course in Steps 3 and 4 below. Visit Course Room & Instructor Allocation afterwards to review or adjust room placements and assign instructor teams.

Nobody gets a course here. Everyone pasted in starts unallocated — that only happens deliberately, in Step 3 below, once placement dates have been checked for everyone (Step 2).

Step 2 — Check placement dates (Pharmacy only)

Pharmacy MPharm is the only programme that actually has placement dates, so this step only matters for them, since every other programme is checked automatically the moment they're added in Step 1. Paste rows straight from a placement lead's sheet — accepts either Student ID, last name, first name, email, start date, end date (the real Pharmacy export) or the older first name, last name, email, start date, end date, dates as DD/MM/YYYY. A pasted header row is dropped automatically. Matched to candidates already added in Step 1 by email — this also clears them for allocation in Step 3. A student can have several rows (several separate placement blocks); each one is added to their file, so re-pasting the same sheet again won't create duplicates. A course runs on 3 consecutive Mondays (worked out from the date set on Stage 1 Settings) — if any of those 3 Mondays falls inside one of a candidate's placement blocks, that's a clash, flagged here and in All candidates below. Nothing is saved until you confirm.

Someone repeating (absence, need to redo) gets a fresh record on the new course rather than editing their old one in place — paste them in above as normal, then use Link repeat on either their old or new row to connect the two records for reference. Nothing else changes; it just stops an old attempt reading as still-pending once you can see it led to a later one.

Recovers from a bad "Allocate now" run — clears the course and room off every allocated candidate so they go back to unallocated and can be run through Step 3 again. Nobody's record is deleted, nothing from Step 1 or Step 2 (name, email, degree, placement dates) is touched or lost — only course and room are cleared. Needs typing a confirmation phrase, on top of the usual two "are you sure" prompts, since this is the one that undoes a big run in one click.

For clearing out a prepped-but-not-yet-allocated batch — test rows, or a real batch you've decided not to run with — before it's been through Step 3. Anyone already allocated (has a course) is never touched by this, allocated or not doesn't matter once Delete all unallocated runs, it only ever looks at who's still unallocated.

For clearing out practice data regardless of allocation status — matches anyone whose email contains .test@, which is how every test batch generated for this site has been addressed. Real candidates never match this, so it's safe to run even once some test rows have been allocated.

Import assessment outcomes (after the course has run)

A separate, later task — not part of adding, checking or allocating candidates above. Once a course has actually run, paste rows from your outcomes sheet: email, pass/fail, more than 2 attempts. Matched by email against the candidates already added above. Pass/fail accepts "pass", "fail", "passed", "failed", "exempt" (case doesn't matter) — anything else is flagged so it's not silently guessed. Attempts accepts a number (e.g. 3) or yes/no. Nothing is saved until you confirm.
